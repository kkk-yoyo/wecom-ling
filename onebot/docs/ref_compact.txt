[pNormal] {font=微软雅黑 sz=14.0 b=True} 使用前
[pNormal] {font=微软雅黑 sz=10.5 b=None} 先做这几件事
[pNormal] {font=微软雅黑 sz=10.5 b=None} 1. 在 Windows 上用管理员身份打开微灵。不要先开企业微信。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 2. 第一次打开会要卡密。把本机机器码发给商家，拿到卡密后粘贴，点激活。激活成功后再进主界面。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 3. 本文先写完企业微信，再写个人微信。两边各自选 HTTP 或 WebSocket，不要混用地址。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 4. 账号面板里要出现对应账号并且在线。没有在线账号时，后面怎么调都没有反应。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 电脑重启后：先开微灵，再从微灵里登录，不要从桌面直接打开微信或企业微信。HTTP 确认本机服务在跑；WebSocket 确认状态是「已连接」。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 两种方式怎么选
[pNormal] {font=微软雅黑 sz=10.5 b=None} 企微和个微各自选一次，可以一个用 HTTP、另一个用 WebSocket。
[pNormal] {font=微软雅黑 sz=10.5 b=None} HTTP：你的服务端主动请求微灵，微灵再把收到的消息 POST 到你填的回调地址。微灵和你的服务端如果不在同一台机器，微灵这边通常还要做内网穿透，否则你访问不到它的端口，它也访问不到你的回调。
[pNormal] {font=微软雅黑 sz=10.5 b=None} WebSocket：微灵主动连你的服务端。收消息、下指令都走这一条连接。一般不需要内网穿透。推荐新对接用这种方式。
[pNormal] {font=微软雅黑 sz=16.0 b=True} 企业微信
[pNormal] {font=None sz=None b=None} 选中 5.0.13.6005 时，对外指令码和回调通道不变。这一版才会多出第「五、仅企业微信 5.0.13.6005」里的事件和字段。更早版本没有。
[pNormal] {font=微软雅黑 sz=12.0 b=True} 企业微信：HTTP 怎么接
[pNormal] {font=微软雅黑 sz=11.0 b=True} 3.1 微灵这边怎么填
[pNormal] {font=微软雅黑 sz=10.5 b=None} 1. 「企业微信」页点「自动检测」或手动选对本机企微版本，再点「登录新账号」扫码。不要从桌面直接打开企业微信。账号面板里要看到在线账号，client 填这个编号。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 2. 通信方式选 HTTP。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 3. 点「编辑」，填写「事件通知 URL」，保存。必须以 http:// 或 https:// 开头。示例：http://192.168.1.100:8080/callback
[pNormal] {font=微软雅黑 sz=10.5 b=None} 4. 「本机配置」页里 HTTP 服务必须是「运行中」。默认端口 8060，改端口后要重启服务。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 5. 你的服务端不在这台电脑上时：「内网穿透」要处于运行中，并把穿透后的对外地址配给你的服务端。事件通知 URL 必须是微灵这台电脑访问得到的地址。
[pNormal] {font=微软雅黑 sz=11.0 b=True} 3.2 你怎么给微灵下指令
[pNormal] {font=Consolas sz=9.0 b=None} POST http://微灵IP:8060/api/Client/ExecCommand
[pNormal] {font=微软雅黑 sz=10.5 b=None} Content-Type: application/json
[pNormal] {font=微软雅黑 sz=10.5 b=None} 请求体就是一条指令，type、data、client 放在最外层：
[pNormal] {font=Consolas sz=9.0 b=None} {
[pNormal] {font=Consolas sz=9.0 b=None} "type": 11029,
[pNormal] {font=Consolas sz=9.0 b=None} "data": {
[pNormal] {font=Consolas sz=9.0 b=None} "conversation_id": "S:自己的user_id_对方的user_id",
[pNormal] {font=Consolas sz=9.0 b=None} "content": "你好"
[pNormal] {font=Consolas sz=9.0 b=None} },
[pNormal] {font=Consolas sz=9.0 b=None} "client": 1
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=微软雅黑 sz=10.5 b=None} 字段说明：
[pNormal] {font=微软雅黑 sz=10.5 b=None} type：指令码，见本文后半部分。
[pNormal] {font=微软雅黑 sz=10.5 b=None} data：这条指令自己的参数。
[pNormal] {font=微软雅黑 sz=10.5 b=None} client：账号面板里的客户端编号。必填。已断开的账号会返回失败。
[pNormal] {font=微软雅黑 sz=10.5 b=None} getData：查询类指令要结果时传 true。发消息这类不需要结果的不要传，传了会一直等到超时。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 成功时 HTTP 正文大致是：
[pNormal] {font=Consolas sz=9.0 b=None} {
[pNormal] {font=Consolas sz=9.0 b=None} "code": 200,
[pNormal] {font=Consolas sz=9.0 b=None} "msg": "请求成功！",
[pNormal] {font=Consolas sz=9.0 b=None} "data": "执行结果",
[pNormal] {font=Consolas sz=9.0 b=None} "time": 1710000000
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=微软雅黑 sz=10.5 b=None} code 为 200 表示成功，其他值表示失败，原因在 msg。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 下载 CDN 文件（type 11170 或 11171）成功时，HTTP 直接返回文件二进制，不是上面的 JSON。请按文件流保存。
[pNormal] {font=微软雅黑 sz=11.0 b=True} 3.3 微灵怎么把消息推给你
[pNormal] {font=微软雅黑 sz=10.5 b=None} 企业微信里发生的事件，微灵会用 POST 把 JSON 发到你填的事件通知 URL。正文就是事件本身，例如：
[pNormal] {font=Consolas sz=9.0 b=None} {
[pNormal] {font=Consolas sz=9.0 b=None} "type": 11041,
[pNormal] {font=Consolas sz=9.0 b=None} "client": 1,
[pNormal] {font=Consolas sz=9.0 b=None} "robot_id": "当前登录用户的user_id",
[pNormal] {font=Consolas sz=9.0 b=None} "data": {
[pNormal] {font=Consolas sz=9.0 b=None} "conversation_id": "S:xxx_xxx",
[pNormal] {font=Consolas sz=9.0 b=None} "content": "你好",
[pNormal] {font=Consolas sz=9.0 b=None} "receiver": "当前登录用户的user_id"
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=微软雅黑 sz=10.5 b=None} client、robot_id 是微灵补上的。type 含义见「通知事件」。你的接口尽快返回 HTTP 2xx 即可，微灵不解析响应正文。回调最多等 5 秒，超时或非 2xx 只记日志，不会重推。不要在这个请求里做耗时处理。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 没收到消息时按这个顺序查：账号是否在线、HTTP 服务是否运行中、事件通知 URL 是否已保存、外网时穿透是否运行、日志里有没有回调失败。
[pNormal] {font=微软雅黑 sz=11.0 b=True} 3.4 企微 HTTP 的 Java 示例
[pNormal] {font=微软雅黑 sz=10.5 b=None} Spring Boot 即可，用 spring-boot-starter-web。微灵把事件 POST 到你填的地址；你再 POST 到微灵的 8060 下指令。回调里尽快返回，不要在这个请求里等待外部接口。
[pNormal] {font=Consolas sz=9.0 b=None} import org.springframework.http.ResponseEntity;
[pNormal] {font=Consolas sz=9.0 b=None} import org.springframework.web.bind.annotation.PostMapping;
[pNormal] {font=Consolas sz=9.0 b=None} import org.springframework.web.bind.annotation.RequestBody;
[pNormal] {font=Consolas sz=9.0 b=None} import org.springframework.web.bind.annotation.RestController;
[pNormal] {font=Consolas sz=9.0 b=None} import org.springframework.web.client.RestTemplate;
[pNormal] {font=Consolas sz=9.0 b=None} import com.fasterxml.jackson.databind.JsonNode;
[pNormal] {font=Consolas sz=9.0 b=None} import com.fasterxml.jackson.databind.ObjectMapper;
[pNormal] {font=Consolas sz=9.0 b=None} import java.util.LinkedHashMap;
[pNormal] {font=Consolas sz=9.0 b=None} import java.util.Map;
[pNormal] {font=Consolas sz=9.0 b=None} @RestController
[pNormal] {font=Consolas sz=9.0 b=None} public class WeComHttpDemo {
[pNormal] {font=Consolas sz=9.0 b=None} private final ObjectMapper json = new ObjectMapper();
[pNormal] {font=Consolas sz=9.0 b=None} private final RestTemplate http = new RestTemplate();
[pNormal] {font=Consolas sz=9.0 b=None} // 微灵「事件通知 URL」填：http://你的主机:端口/wx/callback
[pNormal] {font=Consolas sz=9.0 b=None} @PostMapping("/wx/callback")
[pNormal] {font=Consolas sz=9.0 b=None} public ResponseEntity<String> onEvent(@RequestBody String body) throws Exception {
[pNormal] {font=Consolas sz=9.0 b=None} JsonNode event = json.readTree(body);
[pNormal] {font=Consolas sz=9.0 b=None} int type = event.path("type").asInt();
[pNormal] {font=Consolas sz=9.0 b=None} int client = event.path("client").asInt();
[pNormal] {font=Consolas sz=9.0 b=None} String text = event.path("data").path("content").asText("");
[pNormal] {font=Consolas sz=9.0 b=None} // type 11041 是收到消息。这里尽快返回，耗时逻辑放到别的线程。
[pNormal] {font=Consolas sz=9.0 b=None} return ResponseEntity.ok("ok");
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=Consolas sz=9.0 b=None} // 给在线企微发文本。发消息不要带 getData。
[pNormal] {font=Consolas sz=9.0 b=None} public String sendText(int client, String conversationId, String content) {
[pNormal] {font=Consolas sz=9.0 b=None} Map<String, Object> data = new LinkedHashMap<String, Object>();
[pNormal] {font=Consolas sz=9.0 b=None} data.put("conversation_id", conversationId);
[pNormal] {font=Consolas sz=9.0 b=None} data.put("content", content);
[pNormal] {font=Consolas sz=9.0 b=None} Map<String, Object> body = new LinkedHashMap<String, Object>();
[pNormal] {font=Consolas sz=9.0 b=None} body.put("type", 11029);
[pNormal] {font=Consolas sz=9.0 b=None} body.put("client", client);
[pNormal] {font=Consolas sz=9.0 b=None} body.put("data", data);
[pNormal] {font=Consolas sz=9.0 b=None} return http.postForObject(
[pNormal] {font=Consolas sz=9.0 b=None} "http://微灵IP:8060/api/Client/ExecCommand", body, String.class);
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=微软雅黑 sz=12.0 b=True} 企业微信：WebSocket 怎么接
[pNormal] {font=微软雅黑 sz=11.0 b=True} 4.1 谁连谁
[pNormal] {font=微软雅黑 sz=10.5 b=None} 微灵是客户端，你的服务端是 WebSocket 服务端。微灵主动连过来。你不要去连微灵。
[pNormal] {font=微软雅黑 sz=11.0 b=True} 4.2 微灵这边怎么填
[pNormal] {font=微软雅黑 sz=10.5 b=None} 1. 「企业微信」页通信方式选 WebSocket。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 2. 连接地址填你的服务端地址，ws:// 或 wss://。只填主机时，微灵会自动补上路径 /wx/ws。建议直接填完整地址，例如 ws://192.168.1.100:8080/wx/ws
[pNormal] {font=微软雅黑 sz=10.5 b=None} 3. Token 填你约定的口令。微灵会把它追加到地址上：ws://192.168.1.100:8080/wx/ws?token=你的Token
[pNormal] {font=微软雅黑 sz=10.5 b=None} 4. 点「连接」。状态必须变成「已连接」。停在「连接中」就再等；是「未连接」就核对地址、Token，以及这台电脑能不能访问你的服务端。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 5. 地址和 Token 都填了之后，下次打开微灵会自动重连。断线后按 1 秒、2 秒、4 秒、8 秒、16 秒重连，之后固定 30 秒。连上之后，或网络恢复、本机地址变化时，间隔重新从 1 秒算。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 个人微信是另一条连接，路径是 /personal-wx/ws，不要和企微这条混用。本文指令码只适用于企业微信。
[pNormal] {font=微软雅黑 sz=11.0 b=True} 4.3 帧格式
[pNormal] {font=微软雅黑 sz=10.5 b=None} 除文件分片外，消息都是一条文本 JSON：
[pNormal] {font=Consolas sz=9.0 b=None} {
[pNormal] {font=Consolas sz=9.0 b=None} "id": "本次消息的唯一编号",
[pNormal] {font=Consolas sz=9.0 b=None} "action": "动作",
[pNormal] {font=Consolas sz=9.0 b=None} "payload": {}
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=微软雅黑 sz=10.5 b=None} id 用 UUID 即可。请求和响应必须使用同一个 id，用来对上是哪一条指令。
[pNormal] {font=微软雅黑 sz=11.0 b=True} 4.4 连上之后微灵先发 hello
[pNormal] {font=Consolas sz=9.0 b=None} {
[pNormal] {font=Consolas sz=9.0 b=None} "id": "新的uuid",
[pNormal] {font=Consolas sz=9.0 b=None} "action": "hello",
[pNormal] {font=Consolas sz=9.0 b=None} "payload": {
[pNormal] {font=Consolas sz=9.0 b=None} "clientName": "微灵里填的客户端名称",
[pNormal] {font=Consolas sz=9.0 b=None} "channel": "wecom"
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=微软雅黑 sz=10.5 b=None} 收到 hello 且 channel 为 wecom，就表示这条连接是企业微信通道。你不需要回复 hello。
[pNormal] {font=微软雅黑 sz=11.0 b=True} 4.5 心跳
[pNormal] {font=微软雅黑 sz=10.5 b=None} 微灵每 20 秒发一次 ping。这是应用层 JSON，不是 WebSocket 协议自带的 Ping 帧：
[pNormal] {font=Consolas sz=9.0 b=None} { "id": "uuid", "action": "ping", "payload": {} }
[pNormal] {font=微软雅黑 sz=10.5 b=None} 你必须立刻用同一个 id 回 pong：
[pNormal] {font=Consolas sz=9.0 b=None} { "id": "同一个uuid", "action": "pong", "payload": {} }
[pNormal] {font=微软雅黑 sz=10.5 b=None} 后端必须配合。收到 ping 后立刻用同一个 id 回 pong，微灵收到 pong 才算心跳成功。超过 30 秒没有 pong，微灵会断开并重连。检查发生在下一次发 ping 时，所以实际大约 40 秒能发现死连接。后端只要应答即可，不必自己发 ping，也不必因为长时间没心跳去踢掉连接。你也可以主动发 ping，微灵会回 pong。个微 WebSocket 的心跳和重连与这里相同，两条连接各自心跳，都要回 pong。
[pNormal] {font=微软雅黑 sz=11.0 b=True} 4.6 微灵怎么把消息推给你
[pNormal] {font=微软雅黑 sz=10.5 b=None} 事件用 action=event 推过来。payload 就是和 HTTP 回调同一份 JSON：
[pNormal] {font=Consolas sz=9.0 b=None} {
[pNormal] {font=Consolas sz=9.0 b=None} "id": "uuid",
[pNormal] {font=Consolas sz=9.0 b=None} "action": "event",
[pNormal] {font=Consolas sz=9.0 b=None} "payload": {
[pNormal] {font=Consolas sz=9.0 b=None} "type": 11041,
[pNormal] {font=Consolas sz=9.0 b=None} "client": 1,
[pNormal] {font=Consolas sz=9.0 b=None} "robot_id": "当前登录用户的user_id",
[pNormal] {font=Consolas sz=9.0 b=None} "data": {
[pNormal] {font=Consolas sz=9.0 b=None} "conversation_id": "S:xxx_xxx",
[pNormal] {font=Consolas sz=9.0 b=None} "content": "你好",
[pNormal] {font=Consolas sz=9.0 b=None} "receiver": "当前登录用户的user_id"
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=微软雅黑 sz=10.5 b=None} 你不需要回复 event。WebSocket 未连接时，这条事件会被丢掉，不会改走 HTTP。
[pNormal] {font=微软雅黑 sz=11.0 b=True} 4.7 你怎么给微灵下指令
[pNormal] {font=微软雅黑 sz=10.5 b=None} 发 action=command。payload 与 HTTP 的请求体完全相同，仍然包含 type、data、client，查询时同样带 getData：
[pNormal] {font=Consolas sz=9.0 b=None} {
[pNormal] {font=Consolas sz=9.0 b=None} "id": "指令uuid",
[pNormal] {font=Consolas sz=9.0 b=None} "action": "command",
[pNormal] {font=Consolas sz=9.0 b=None} "payload": {
[pNormal] {font=Consolas sz=9.0 b=None} "type": 11029,
[pNormal] {font=Consolas sz=9.0 b=None} "client": 1,
[pNormal] {font=Consolas sz=9.0 b=None} "data": {
[pNormal] {font=Consolas sz=9.0 b=None} "conversation_id": "S:xxx_xxx",
[pNormal] {font=Consolas sz=9.0 b=None} "content": "你好"
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=微软雅黑 sz=10.5 b=None} 微灵执行完后回 action=command_result，id 与你发出的指令相同：
[pNormal] {font=Consolas sz=9.0 b=None} {
[pNormal] {font=Consolas sz=9.0 b=None} "id": "指令uuid",
[pNormal] {font=Consolas sz=9.0 b=None} "action": "command_result",
[pNormal] {font=Consolas sz=9.0 b=None} "payload": {

[pNormal] {font=微软雅黑 sz=11.0 b=True} 4.8 下载文件时多出来的二进制帧
[pNormal] {font=微软雅黑 sz=10.5 b=None} type 为 11170 或 11171 时，微灵不会在 JSON 里塞文件内容。顺序是：
[pNormal] {font=微软雅黑 sz=10.5 b=None} 1. 文本帧 action=file_start，id 为指令 id。payload 含 name、size、contentType。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 2. 若干二进制帧。单帧最大 64KB，文件最大 100MB。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 3. 文本帧 action=file_end。payload 为 { "ok": true, "size": 文件字节数 }。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 4. 最后仍有一条 command_result。payload 里 file 为 true，并带 fileName、contentType、size。文件内容以前面的二进制帧为准。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 二进制帧布局（大端）：
[pNormal] {font=微软雅黑 sz=10.5 b=None} 4 字节魔数，固定是 ASCII：WXFL
[pNormal] {font=微软雅黑 sz=10.5 b=None} 2 字节：后面指令 id 的字节长度
[pNormal] {font=微软雅黑 sz=10.5 b=None} N 字节：指令 id 的 UTF-8
[pNormal] {font=微软雅黑 sz=10.5 b=None} 4 字节：分片序号 seq，从 0 开始
[pNormal] {font=微软雅黑 sz=10.5 b=None} 1 字节：是否最后一片，1 表示是
[pNormal] {font=微软雅黑 sz=10.5 b=None} 剩余字节：这一片的文件内容
[pNormal] {font=微软雅黑 sz=10.5 b=None} 按 seq 顺序拼接，直到 last 为 1。
[pNormal] {font=微软雅黑 sz=11.0 b=True} 4.9 没反应时查什么
[pNormal] {font=微软雅黑 sz=10.5 b=None} 只查这几项：状态是不是「已连接」、账号面板里有没有在线账号、你的服务端有没有把 command 的 id 原样带回。不要去查 HTTP 的事件通知 URL 和内网穿透，WebSocket 用不到它们。

[pNormal] {font=None sz=None b=None} 五、仅企业微信 5.0.13.6005
[pNormal] {font=None sz=None b=None} 下面这些只在微灵选中的企业微信版本是 5.0.13.6005 时才会出现。5.0.0.6008 和 5.0.3.6005 不推这些新事件，同一条旧接口也不会多出这些字段。对接时看字段在不在，不要假设旧版本也有。
[pNormal] {font=None sz=None b=None} 5.1 新通知事件（仅 5.0.13.6005 支持）
[pNormal] {font=None sz=None b=None} 11201 连接断开。账号还在，只是观察到连接中断。这是实验通知。connection_state 为 unknown 时不能当成离线，也不要据此把账号标成退出。data 字段：event（固定 disconnected）、event_id、account_id、user_id、observed_at_ms（观察到变化的 Unix 毫秒）、source、connection_state、pid。source 可能是 client_context、client_connection_callback、process_replacement。

[pNormal] {font=微软雅黑 sz=16.0 b=True} 个人微信
[pNormal] {font=微软雅黑 sz=10.5 b=None} 从这里开始只写个人微信。不要使用上面的企业微信 type 码和 /api/Client 路径。
[pNormal] {font=微软雅黑 sz=14.0 b=True} 个人微信怎么对接
[pNormal] {font=微软雅黑 sz=10.5 b=None} 个微不要使用企业微信的 type 码，也不要调用 /api/Client/ExecCommand。指令名和参数见本文「个人微信指令」「个人微信事件」。微灵只负责转发。
[pNormal] {font=微软雅黑 sz=11.0 b=True} 5.1 微灵这边怎么准备
[pNormal] {font=微软雅黑 sz=10.5 b=None} 1. 打开「个人微信」页，填好本机 Weixin.exe 的完整路径。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 2. 通信方式选 HTTP 或 WebSocket，只选一种。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 3. 点「启动个人微信」，等窗口起来后再登录。不要自己先打开已经在运行的微信再指望注入。个微只能在微灵拉起进程时注入，已经开着的微信注入不进去。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 4. 账号面板里出现该微信，状态在线。指令里的 client 填这个账号的编号。这个编号就是该实例的本地端口，也可以改填这个号的 wxid。
[pNormal] {font=微软雅黑 sz=11.0 b=True} 5.2 个人微信：HTTP
[pNormal] {font=微软雅黑 sz=10.5 b=None} 微灵这边：
[pNormal] {font=微软雅黑 sz=10.5 b=None} 1. 通信方式选 HTTP。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 2. 填写个微自己的「事件通知 URL」并保存。这是个微专用地址，不要填成企微那个。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 3. 「本机配置」里 HTTP 服务必须是「运行中」，默认端口仍是 8060。企微和个微共用这一个 HTTP 端口，靠路径区分。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 下指令：
[pNormal] {font=Consolas sz=9.0 b=None} POST http://微灵IP:8060/api/PersonalWeChat/ExecCommand
[pNormal] {font=微软雅黑 sz=10.5 b=None} Content-Type: application/json
[pNormal] {font=Consolas sz=9.0 b=None} {
[pNormal] {font=Consolas sz=9.0 b=None} "client": "19088",
[pNormal] {font=Consolas sz=9.0 b=None} "action": "send_text_msg",
[pNormal] {font=Consolas sz=9.0 b=None} "data": {}
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=微软雅黑 sz=11.0 b=True} client：账号面板上的编号，或该微信的 wxid。必填。
[pNormal] {font=微软雅黑 sz=10.5 b=True} action：个微指令名，例如 send_text_msg。具体名字和 data 字段看上面的 Apifox 文档。必填。
[pNormal] {font=微软雅黑 sz=10.5 b=None} data：这条指令的参数。没有参数时传 {}。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 查当前有哪些个微在线：
[pNormal] {font=Consolas sz=9.0 b=None} GET http://微灵IP:8060/api/PersonalWeChat/Clients
[pNormal] {font=微软雅黑 sz=10.5 b=None} 返回每条里的 clientId、wxId、nickname、isOnline。clientId 就是下指令时的 client。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 由微灵拉起一个新的个人微信：
[pNormal] {font=Consolas sz=9.0 b=None} GET http://微灵IP:8060/api/PersonalWeChat/OpenWeixin
[pNormal] {font=微软雅黑 sz=10.5 b=None} 不传 path 时使用微灵里已保存的 Weixin.exe 路径。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 成功时 HTTP 正文同样是 code、msg、data、time。code 为 200 表示微灵这一层成功。data 里是个微自己的返回，常见成功码是 0、1、200。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 下载语音、图片、视频、文件时，action 使用 download_voice、download_img、download_video、download_file。HTTP 成功时直接返回文件二进制，不是 JSON。语音可以在 data 里带 format 为 mp3 或 wav，微灵会转码后再返回；不带 format 则返回原始文件。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 发图片、文件、语音时，data 里可以给微灵所在电脑上的本地路径，也可以给 url 或 base64。微灵会先落成临时文件再转发给个微。对应 action：send_image_msg、send_file_msg、send_voice、send_mp3_voice。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 事件推送：个人微信里发生的事件，微灵 POST 到个微的事件通知 URL。正文是个微原始事件，并额外加上：
[pNormal] {font=微软雅黑 sz=10.5 b=None} client：该实例编号
[pNormal] {font=微软雅黑 sz=10.5 b=None} robot_id：当前登录 wxid
[pNormal] {font=微软雅黑 sz=10.5 b=None} client_name：微灵里填的个微客户端名称，没填就没有
[pNormal] {font=微软雅黑 sz=10.5 b=None} client_url：客户端地址，没填就没有
[pNormal] {font=微软雅黑 sz=10.5 b=None} 原始事件里用 event_type 区分类型（有的包写作 even_type），文字说明在 event_desc。各类型的字段见本文「个人微信事件」。你的接口尽快返回 HTTP 2xx 即可。回调最多等 5 秒，超时不会重推。不要在这个请求里做耗时处理。

[pNormal] {font=微软雅黑 sz=11.0 b=True} 5.3 个人微信：WebSocket
[pNormal] {font=微软雅黑 sz=10.5 b=None} 帧格式、文件分片和企业微信那一节相同。心跳也相同：微灵每 20 秒发 ping，后端必须用同一个 id 回 pong；大约 40 秒没有 pong 就断开。重连从 1 秒翻倍，最长 30 秒。只有下面这些不同。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 微灵这边：
[pNormal] {font=微软雅黑 sz=10.5 b=None} 1. 「个人微信」页通信方式选 WebSocket。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 2. 连接地址填你的服务端。只填主机时，微灵自动补路径 /personal-wx/ws。建议写完整地址，例如 ws://192.168.1.100:8080/personal-wx/ws
[pNormal] {font=微软雅黑 sz=10.5 b=None} 3. Token 填你约定的口令。微灵会追加为 ?token=你的Token。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 4. 点「连接」，状态必须是「已连接」。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 连上后微灵发 hello，channel 是 personal，不是 wecom：
[pNormal] {font=Consolas sz=9.0 b=None} {
[pNormal] {font=Consolas sz=9.0 b=None} "id": "uuid",
[pNormal] {font=Consolas sz=9.0 b=None} "action": "hello",
[pNormal] {font=Consolas sz=9.0 b=None} "payload": {
[pNormal] {font=Consolas sz=9.0 b=None} "clientName": "微灵里填的个微客户端名称",
[pNormal] {font=Consolas sz=9.0 b=None} "channel": "personal"
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=微软雅黑 sz=10.5 b=None} 收到 channel 为 personal 才按个微处理。企微那条连接的 channel 是 wecom，两条连接不要接到同一个业务处理里。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 事件仍然是 action=event。payload 就是 5.2 里那份 POST 正文（原始事件加上 client、robot_id 等）。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 下指令仍然是 action=command，但 payload 用个微的请求体，不是企微的 type：
[pNormal] {font=Consolas sz=9.0 b=None} {
[pNormal] {font=Consolas sz=9.0 b=None} "id": "指令uuid",
[pNormal] {font=Consolas sz=9.0 b=None} "action": "command",
[pNormal] {font=Consolas sz=9.0 b=None} "payload": {
[pNormal] {font=Consolas sz=9.0 b=None} "client": "19088",
[pNormal] {font=Consolas sz=9.0 b=None} "action": "send_text_msg",
[pNormal] {font=Consolas sz=9.0 b=None} "data": {}
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=Consolas sz=9.0 b=None} }
[pNormal] {font=微软雅黑 sz=10.5 b=None} 注意：外层 action 固定写 command，里层 payload.action 才是个微指令名。
[pNormal] {font=微软雅黑 sz=10.5 b=None} 回包仍是同一个 id 的 command_result，payload.code 为 200 表示成功。
[pNormal] {font=微软雅黑 sz=10.5 b=None} download_voice、download_img、download_video、download_file 的文件内容不在 JSON 里，走企业微信 WebSocket 里写过的 file_start、WXFL 二进制分片、file_end，最后再来一条 command_result。
[pNormal] {font=微软雅黑 sz=10.5 b=None} WebSocket 没连上时，个微事件会被丢掉，不会改走 HTTP。
